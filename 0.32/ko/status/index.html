현황

이 페이지들이 설명하는 fileshare 릴리스, 각 릴리스가 추가한 것, 실제 클라이언트로 검증된 것, 그리고 아직 구현되지 않은 것.

이 페이지들은 fileshare v0.32.0을 설명합니다.

릴리스 바이너리를 govulncheck -mode binary로 확인하기

v0.31.2부터 릴리스 바이너리는 -s -w 대신 -ldflags "-w"로 빌드됩니다. DWARF 디버그 정보는 제거되고 심볼 테이블은 유지됩니다. govulncheck가 이 테이블을 읽으므로, 내려받은 바이너리에서는 실제로 링크된 패키지의 취약점만 보고됩니다.

govulncheck -mode binary ./fileshare

심볼이 제거된 바이너리에서는 govulncheck가 모듈 수준으로 되돌아가, 링크되지 않은 패키지의 취약점(예: GO-2026-5932, golang.org/x/crypto/openpgp)도 보고합니다. 바이너리는 7~10 % 커지며, 기능상 변경은 없습니다.

보안: v0.31.0이 아니라 v0.31.1을 사용하세요

Go 1.27.2에서 govulncheck는 fileshare에서 GO-2026-6809에 도달할 수 있다고 보고합니다. crypto/x509의 Certificate.Verify가 알려진 침해된 중간 인증서를 거부하지 않았습니다. Go 1.26.10과 1.27.3에서 수정되었습니다. 더 오래된 Go로 빌드한 v0.31.0의 릴리스 바이너리는 영향을 받습니다. v0.31.1은 Go 1.27.3으로 빌드되고 go 지시어도 1.27.3이므로, go install이 스스로 수정된 툴체인으로 전환합니다. 릴리스 바이너리는 go version -m에서 go1.27.3을 보고합니다. 세 UI도 같은 방식으로 다시 빌드되었습니다(portal v0.3.2, console v0.3.5, explorer v0.3.2). 툴체인만 바뀌었고 동작은 바뀌지 않았습니다.

v0.32.0GOOS=wasip1 GOARCH=wasm에서 빌드되고 서비스됨. go-wasmcontainers 엔진의 WebAssembly 컨테이너로서, WebDAV가 WasmEdge 소켓 확장(stealthrocket/net/wasip1)을 통해 수신 대기. 빌드 태그 nosql,noopenpubkey(전체, gzip 11.5 MB) 또는 WebDAV 전용 세트(gzip 6.5 MB). CI가 둘 다 빌드. wasip1에서는 시그널 처리 없음: 호스트가 모듈을 종료

v0.21.0으로 업그레이드할 때

가득 찬 디렉터리 공유의 응답이 달라집니다. EDQUOT(쿼터)와 ENOSPC가 이제 볼륨만이 아니라 모든 디렉터리 공유에서 하나의 오류, “no space left on device (the share is full)“입니다. WebDAV 500이고 NFS NFS3ERR_IO였던 EDQUOT는 이제 507과NFS3ERR_NOSPC이며, SFTP의 텍스트는 경로 없이 그 문장입니다. SMB는 여전히 접근 거부로 응답합니다. 가득 찬 공유를 참고하십시오.

v0.20.0으로 업그레이드할 때

공급자의 alice는 더 이상 로컬 alice의 공유를 받지 못합니다. 공급자의 이름이 곧 로컬 이름인 사이트는 oidc 블록에 local_names = true를 추가하며(그리고domains를 설정하며), 서버는 이것이 없어 거부한 이름마다 해당 행을 로그에 기록합니다.

v0.19.0으로 업그레이드할 때

start_tls = true 없이 다른 머신의 ldap://를 가리키는 users "ldap" 블록은더 이상 시작되지 않습니다. ldaps:// 또는 StartTLS를 사용하십시오.

v0.17.0으로 업그레이드할 때

한 공유가 다른 공유 안에 있거나, 두 공유가 하나의 소스를 쓰거나, 접근 파일(authorized_keys_file, dsn_file, bind_password_file, ssf의 ca_file)이 공유 안에 있는 구성은 더 이상 시작되지 않으며, 오류가 공유와 경로를 알려 줍니다.

v0.9.0 이후로 업그레이드할 때

인증할 사용자가 있는 상태에서 다른 머신이 접근할 수 있는 주소로 TLS 없이 WebDAV를 제공하는 구성은 더 이상 시작되지 않습니다. tls = true와 tls 블록을 추가하거나, TLS를 종료하는 프록시 뒤에서는 plaintext = true를 추가하십시오.TLS를 참고하십시오.

검증됨

이 프로젝트가 작성하지 않은 클라이언트가 실제로 수행하도록 한 것들이며, 코드에 대한 주장이 아닙니다.

  • macOS는 curl이 같은 이미지에 WebDAV로 쓰는 동안 공유를 SMB로 마운트하고,WebDAV가 쓴 내용을 다시 읽습니다. 읽기만 가능한 공유에 대한 Bob의 WebDAV 쓰기는403이고, 잘못된 비밀번호는 401입니다.
  • go-smb2 — 이 프로젝트가 작성하지 않은 클라이언트 — 가 CI에서 -race로 SMB를 통한 동시 읽기 스무 건과 WebDAV를 통한 스무 건을 함께 구동합니다.
  • 접근 규칙은 구성만이 아니라 모든 프로토콜을 통해 검사됩니다. alice는 쓸 수 있고 bob은 쓸 수 없는 것이 SMB와 WebDAV 양쪽에서 확인되며, NFS에는 그 공유가 아예 제공되지 않습니다.
  • SFTP 인증서는 OpenSSH 자체 클라이언트로 검증되며, 이 클라이언트는 인증서를 치워 두면 같은 키를 거부합니다.
  • 인증서 기반 NFS ID는 go-filesystems/nfs의 CI에서 실제 Linux 클라이언트(커널 6.17, ktls-utils 0.9)로 측정했으며, 이를 통해평문 MNT와 tlshd의 함정을 발견했습니다.
  • KRL의 서명되지 않은 형태는 측정 결과입니다. OpenSSH 9.6과 10.3은 서명된 KRL을 읽고 서명을 건너뜁니다(go-authn/krl, 두 버전 모두 대조).
  • go-authn/bridge의 상호 운용 레인 (#12,#17)이 fileshare v0.13.0을 실제 bridge에 대해 판정합니다. KRL, NFS의 CRL, 공유 신호로 폐기된 WebDAV 토큰, 스코프로 비활성화된 IdP, 공유 신호를 통한 opkssh입니다.

아직 지원하지 않는 것

S3를 통한 쓰기. PUT과 DELETE는 403으로 응답합니다. 라이브러리는 쓸 수 있지만, 사용자가 읽기만 할 수 있는 공유는 SFTP와 같은 지점에서 거부해야 하는데 아직 연결되지 않았습니다. 거부하는 편이 반쯤 쓰인 오브젝트보다 낫습니다.

S3를 통한 OIDC 토큰. 토큰은 WebDAV에서만 동작하며 다른 곳에서는 동작하지 않습니다. S3의 일반적인 경로는 STSAssumeRoleWithWebIdentity로, 토큰을 클라이언트가 이후 서명에 쓰는 임시 자격 증명으로 교환합니다. 베어러 토큰을 수락하는 것과는 다른 메커니즘이며 구현되어 있지 않습니다.

admin 또는 metrics 블록이 있는 --isolate. 거부됩니다. API 변경을 적용할 단일 프로세스가 없기 때문입니다.프로토콜마다 하나의 프로세스를 참고하십시오.

공유 Linux NFS 클라이언트에서 인증서 기반의 사용자별 구분. Linux 클라이언트는 인증서를 마운트에 연결하므로 마운트의 모든 사용자가 인증서가 지정하는 사용자가 됩니다. 이는 클라이언트의 속성이며, 그곳에서의 답은 sec=krb5입니다.보장할 수 없는 것을 참고하십시오.

S3 자체는 출시되었습니다. 공유는 버킷이며, SFTP가 사용하는 것과 같은 사용자별 트리 위에서 제공됩니다.

측정되었으며, 측정된 것으로 서술합니다

이 페이지들의 주장 중 결함의 재현이 아니라 보험이나 측정인 것들이며, 소스에도 그렇게 기록되어 있습니다.

  • 감싸지 않은 fat32 드라이버를 -race로 실행하며 고루틴 여덟 개가 쓰기를 해도 오늘 경쟁 상태가 발생하지 않습니다. 공유 잠금은 계약에 대한 보험(go-filesystems/interface는 경로 기반 동시 호출에 대해 아무것도 보장하지 않음)이지, 관찰된 실패의 수정이 아닙니다.
  • 빌드 태그 크기는 측정한 값입니다.hashicorp/go-plugin 단독으로 드는 13.2 MB(플러그인 프레임워크를 택하지 않기로 결정한 근거)와, 관리 API가 가져오는 gRPC의 11.7 MB(nogrpc가 존재하는 이유)를 포함합니다.
  • 그룹 태그용 자체 인증서 확장을 설계하여 Go의 X.509 파서에 대해 측정했고, 파서가 인증서 전체를 거부했습니다. 그래서 그룹은 대신tag URI로 전달됩니다.
