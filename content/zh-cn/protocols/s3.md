```hcl
serve "s3" { addr = "0.0.0.0:9000" }
```

或者自 v0.9.0 起通过 HTTPS，使用 `tls = true` 和
[`tls` 块]({{< relref "/security/tls.md" >}})：

```hcl
serve "s3" {
  addr = "0.0.0.0:9000"
  tls  = true
}
```

这是第五个协议，它使映像可以被任何使用对象存储的工具访问，
例如备份工具、数据管道、`rclone`、浏览器的 `fetch()`。**无需挂载任何东西。**

```
GET /                      the shares this person may use, as buckets
GET /photos?list-type=2    the files in that share, as keys
GET /photos/holiday.jpg    the file itself, Range and all
```

## 共享就是存储桶 {#a-share-is-a-bucket}

它基于 **SFTP 使用的同一棵每用户目录树**提供：这是一个顶层
为此人可以使用的各个共享的文件系统。因此 alice 无权使用的共享，
就不是 alice 能看到的存储桶，访问规则只在一处应用，而不是
复制到第二个协议中。

{{< callout type="info" >}}
**共享内的目录是前缀，而不是对象**

这正是 S3 客户端已有的认识：它们把以分隔符结尾的前缀显示为
文件夹。对目录执行 `GET` 会返回 `NoSuchKey`，因为
返回 200 会让客户端以为可以获取文件夹的字节。
{{< /callout >}}

## 访问密钥就是用户；机密密钥就是其密码 {#an-access-key-is-a-user-the-secret-key-is-their-password}

```sh
export AWS_ACCESS_KEY_ID=alice
export AWS_SECRET_ACCESS_KEY=$(cat alice.pw)
aws --endpoint-url http://attic.example.org:9000 s3 ls
```

SigV4 通过由机密计算 HMAC 来证明持有该机密，密码
从不在网络上传输，与 NTLMv2 完全一样。

{{< callout type="error" >}}
**因此目录服务必须持有密码，而不仅仅是检查密码**

只能*验证*密码的来源，例如 LDAP 绑定或 bcrypt 列，
可以应答 WebDAV，但**无法**应答 S3。

NT 哈希同样不行：它是 SMB 可以使用的 MD4，而无法
由它计算出 HMAC。**只持有 NT 哈希的身份可以通过
SMB 获得服务，而不能通过 S3**，二者相近但并不是同一个答案。
[`check`]({{< relref "/configuration/check.md" >}})会打印出对应的列。
{{< /callout >}}

⛔ 程序中的任何地方都没有 `Password()` 访问器：密码
只能通过 `Identity.Derive` 获得，它接受一个派生函数并返回
其结果。对于 S3，派生函数就是恒等函数，因为 SigV4 的密钥
调度位于 go-filesystems/s3 中；机密只会送到那次签名检查中，
仅为那一个用户，不会去往别处。

## 提供什么 {#what-is-served}

`ListBuckets`、`HeadBucket`、带有前缀、分隔符、max-keys
和续页的 `ListObjectsV2`、`HeadObject`，以及带 `Range` 的 `GetObject`。
SigV4 的两种形式，标头和预签名，均受支持。

对象 API 本身是
[`go-filesystems/s3`](https://github.com/go-filesystems/s3)。

## 拒绝什么，以及原因 {#what-is-refused-and-why}

{{< callout type="warning" >}}
**写入返回 403**

`PUT`、`POST` 和 `DELETE` 会被拒绝，返回 `AccessDenied`（“this export is
read-only”）。fileshare 让 S3 服务器保持只读，因为对于某人
只能读取的共享，必须在与 SFTP 相同的位置拒绝，而这一点尚未
接入；本版本所基于的 go-filesystems/s3 v0.3.0 无论如何都会拒绝
所有写入。拒绝胜过写了一半的对象。
{{< /callout >}}

{{< callout type="warning" >}}
**这里不接受持有者令牌**

[OIDC]({{< relref "/protocols/webdav.md" >}})只在 WebDAV 上有效，其他地方都不行。S3 使用
SigV4 签名进行身份验证，这是对请求的 HMAC，没有可容纳持有者令牌的
字段。

通常的做法是 STS `AssumeRoleWithWebIdentity`，它把 OIDC
令牌换成临时凭据，客户端随后用这些凭据签名。那是
另一种机制，并且**尚未实现**。
{{< /callout >}}

分段上传、版本控制、ACL、策略、生命周期规则、复制和
标签均未实现。设置其中任何一项以及开始分段
上传，都属于写入，和其他写入一样返回 `AccessDenied`。请求其中某一项的
`GET`（`?versioning`、`?acl`、`?tagging`……）不会被区分出来：
查询参数被忽略，返回存储桶的列表或对象。
对于 `list-type=2` 以外的列表、在 `/` 上除 `GET` 之外的任何方法，
以及这里没有任何操作使用的方法，返回 `NotImplemented`。

## 在指向大对象之前值得了解的两个限制 {#two-limits-worth-knowing-before-pointing-it-at-something-large}

**`GetObject` 会把整个对象读入内存。** 驱动接口只提供
`ReadFile`，没有别的，没有 opener，也没有 reader，因此没有可用的
流式读取。256 MiB 的上限会返回 `EntityTooLarge`，而不是让
进程崩溃。

**`LastModified` 是纪元时间。** `filesystem.Stat` 携带 `Mode`、`Size` 和
`Inode`，完全没有修改时间。该字段在 S3
模式中不是可选的，因此必须发送一个值；纪元时间显然不是真实时间，
而 `time.Now()` 则会像是刚刚更改的文件，使每个同步
工具在每次运行时都复制所有内容。
