```hcl
serve "s3" { addr = "0.0.0.0:9000" }
```

或者自 v0.9.0 起通过 HTTPS，使用 `tls = true` 和
[`tls` 块]({{< relref "/security/tls.md" >}})：

```hcl
serve "s3" {
  addr = "0.0.0.0:9000"
  tls  = true
}
```

这是第五个协议，它使映像可以被任何使用对象存储的工具访问，
例如备份工具、数据管道、`rclone`、浏览器的 `fetch()`。**无需挂载任何东西。**

```
GET /                      the shares this person may use, as buckets
GET /photos?list-type=2    the files in that share, as keys
GET /photos/holiday.jpg    the file itself, Range and all
```

## 共享就是存储桶 {#a-share-is-a-bucket}

它基于 **SFTP 使用的同一棵每用户目录树**提供：这是一个顶层
为此人可以使用的各个共享的文件系统。因此 alice 无权使用的共享，
就不是 alice 能看到的存储桶，访问规则只在一处应用，而不是
复制到第二个协议中。

{{< callout type="info" >}}
**共享内的目录是前缀，而不是对象**

这正是 S3 客户端已有的认识：它们把以分隔符结尾的前缀显示为
文件夹。对目录执行 `GET` 会返回 `NoSuchKey`，因为
返回 200 会让客户端以为可以获取文件夹的字节。
{{< /callout >}}

## 访问密钥就是用户；机密密钥就是其密码 {#an-access-key-is-a-user-the-secret-key-is-their-password}

```sh
export AWS_ACCESS_KEY_ID=alice
export AWS_SECRET_ACCESS_KEY=$(cat alice.pw)
aws --endpoint-url http://attic.example.org:9000 s3 ls
```

SigV4 通过由机密计算 HMAC 来证明持有该机密，密码
从不在网络上传输，与 NTLMv2 完全一样。

{{< callout type="error" >}}
**因此目录服务必须持有密码，而不仅仅是检查密码**

只能*验证*密码的来源，例如 LDAP 绑定或 bcrypt 列，
可以应答 WebDAV，但**无法**应答 S3。

NT 哈希同样不行：它是 SMB 可以使用的 MD4，而无法
由它计算出 HMAC。**只持有 NT 哈希的身份可以通过
SMB 获得服务，而不能通过 S3**，二者相近但并不是同一个答案。
[`check`]({{< relref "/configuration/check.md" >}})会打印出对应的列。
{{< /callout >}}

⛔ 程序中的任何地方都没有 `Password()` 访问器：密码
只能通过 `Identity.Derive` 获得，它接受一个派生函数并返回
其结果。对于 S3，派生函数就是恒等函数，因为 SigV4 的密钥
调度位于 go-filesystems/s3 中；机密只会送到那次签名检查中，
仅为那一个用户，不会去往别处。

## 提供什么 {#what-is-served}

`ListBuckets`、`HeadBucket`、带有前缀、分隔符、max-keys
和续页的 `ListObjectsV2`、`HeadObject`，以及带 `Range` 的 `GetObject`。
SigV4 的两种形式，标头和预签名，均受支持。

对象 API 本身是
[`go-filesystems/s3`](https://github.com/go-filesystems/s3)。

## 拒绝什么，以及原因 {#what-is-refused-and-why}

{{< callout type="warning" >}}
**写入返回 403**

`PUT`、`POST` 和 `DELETE` 会被拒绝，返回 `AccessDenied`（“this export is
read-only”）。fileshare 让 S3 服务器保持只读，因为对于某人
只能读取的共享，必须在与 SFTP 相同的位置拒绝，而这一点尚未
接入；本版本所基于的 go-filesystems/s3 v0.3.0 无论如何都会拒绝
所有写入。拒绝胜过写了一半的对象。
{{< /callout >}}

{{< callout type="warning" >}}
**这里不接受持有者令牌**

[OIDC]({{< relref "/protocols/webdav.md" >}})只在 WebDAV 上有效，其他地方都不行。S3 使用
SigV4 签名进行身份验证，这是对请求的 HMAC，没有可容纳持有者令牌的
字段。

做法是 STS `AssumeRoleWithWebIdentity`，它把 OIDC
令牌换成临时凭据，客户端随后用这些凭据签名。自 v0.50.0 起，
此监听器提供它：见[下文](#sts)。
{{< /callout >}}

分段上传、版本控制、ACL、策略、生命周期规则、复制和
标签均未实现。设置其中任何一项以及开始分段
上传，都属于写入，和其他写入一样返回 `AccessDenied`。请求其中某一项的
`GET`（`?versioning`、`?acl`、`?tagging`……）不会被区分出来：
查询参数被忽略，返回存储桶的列表或对象。
对于 `list-type=2` 以外的列表、在 `/` 上除 `GET` 之外的任何方法，
以及这里没有任何操作使用的方法，返回 `NotImplemented`。

## 临时凭据：STS `AssumeRoleWithWebIdentity` {#sts}

自 v0.50.0 起，S3 监听器也响应 AWS STS API（`AssumeRoleWithWebIdentity`，版本 2011-06-15）：
[`oidc` 块]({{< relref "/protocols/webdav.md" >}})的提供方所发的令牌，被换成**会过期**的访问密钥、机密密钥和会话令牌。
`aws`、`rclone` 和 AWS SDK 像对 AWS 那样使用它，没有人持有密码。

```hcl
oidc {
  issuer   = "https://login.example.org"
  audience = "fileshare"
}

serve "s3" {
  addr             = "0.0.0.0:9000"
  tls              = true
  sts              = true      # POST /，Action=AssumeRoleWithWebIdentity
  sts_duration     = "1h"      # 默认值，15m 到 12h
  sts_max_duration = "4h"      # DurationSeconds 最多可要求的值；默认为 sts_duration
  static_keys      = false     # 不再有“访问密钥就是用户”：只有临时凭据签名
}
```

- **令牌**是 `oidc` 块的提供方所发的访问令牌（`typ` 为 `at+jwt`），针对该块的 issuer 和
  audience——没有第二套提供方配置。可以是人的令牌，也可以是机器的：go-authn/bridge 为用私钥认证
  （`private_key_jwt`）的客户端签发的 `client_credentials` 令牌，其 `sub` = 客户端 ID，
  那就是这里的名字。
- ⛔ **它经过与 WebDAV 上的令牌相同的规则。** 对于这里没有任何来源认识的名字，有效令牌也会被拒绝，
  除非 `trust_all = true`，或某个共享的 `oidc:` 规则点了它的名
  （`allow = ["oidc:user:winpc-17"]`）。随后由共享的规则决定什么可见。
- **应答**是 `AccessKeyId`（`ASIA…`）、`SecretAccessKey`、`SessionToken` 和 `Expiration`。
  请求用它们签名，并在 `x-amz-security-token` 中带上会话令牌（**被签名**）。它们是随机的，
  只在内存中，从不写出；重启会使其终止，客户端再次请求。
- ⛔ **有效期 = min(请求的时长, 令牌剩余的时间)。** 凭据绝不会比买到它们的令牌活得更久
  （`sts_duration`，或至多到 `sts_max_duration` 的 `DurationSeconds`，只是上限）。剩余时间
  **不足 6 分钟**的令牌会被 `ExpiredTokenException` 拒绝：AWS SDK 在 `Expiration` 前约 5 分钟续期，
  更短的凭据会被立即、永远地续期。客户端每次交换都出示新的令牌。
- ⛔ **会话在每个请求上都被判断**：它会过期；其会话令牌与其访问密钥绑定；在令牌签发之后提供方撤销
  此人时它即告结束（[共享信号]({{< relref "/security/shared-signals.md" >}})）；配置不再接纳该名字时
  也告结束。
- `Policy`、`PolicyArns` 和第二个 `WebIdentityToken` 会被拒绝，参数必须放在 POST 正文里，
  绝不能放在 URL 中。
- **`static_keys = false`** 关闭“访问密钥就是用户、机密密钥就是其密码”的方式。它需要
  `sts = true`：否则配置在加载时被拒绝，因为一个没人能为之签名的监听器看起来像已配置好。
  在非回环地址上，`sts` 需要 `tls = true`，或在前面终结 TLS 时用 `plaintext = true`。

### 在无人值守的机器上：awscred {#on-an-unattended-machine-awscred}

[`awscred`](https://github.com/go-authn/awscred) v0.1.0 是给持有私钥而没有密码的机器用的 AWS
`credential_process`：它签发一个 `private_key_jwt`，从 go-authn/bridge 取得令牌，调用此端点，
并按 SDK 读取的格式打印凭据。SDK 会在 `Expiration` 之前再次运行它。

```ini
[profile fileshare]
credential_process = awscred --issuer https://login.example.org --client winpc-17 --key /etc/awscred/winpc-17.pem --sts https://s3.example.org
```

⛔ 在 Unix 上，`awscred` 拒绝组或其他用户可读的密钥文件（`chmod 600`）。在 Windows 上文件权限位
没有意义：请把密钥放在服务账户的配置文件目录中，或放在 ACL 只允许该账户的目录里。
Windows CNG 存储或 TPM 中的密钥尚不支持。

### 在代理之后：`trusted_proxies` {#behind-a-proxy-trusted_proxies}

在 `plaintext = true` 所针对的代理之后，所有客户端对下面的速率限制来说都是同一个来源。
请在 `s3` 的 serve 块中列出代理：

```hcl
serve "s3" {
  addr            = "127.0.0.1:9000"
  plaintext       = true
  sts             = true
  trusted_proxies = ["10.0.0.2", "10.0.1.0/29"]
}
```

只有**来自**受信任代理的请求，其关于客户端的说法才会被相信，取 `X-Forwarded-For` 中最右边、
且本身不是受信任代理的那一跳；对其他任何来源，该头会被忽略。

{{< callout type="warning" >}}
**列表必须只列出代理，别的都不要列**

比一台主机更宽的前缀（`/24`、IPv6 的 `/64`）会被接受——代理池，比如 `/29`，是正当的——
并在启动时打印一条警告：在其中可以拥有地址的客户端，会自己选择 `X-Forwarded-For`，
从而选择自己被计入的桶。
{{< /callout >}}

### 限制 {#limits}

- **每个名字 16 个会话**：同名的最老的先出局，其他名字的会话保留（总共 20000）。
- **每个来源地址每分钟 60 个请求**，应答 `429 Throttling`。每个请求，无论有效与否，都在验证令牌
  之前计数。来源是一个 IPv4 地址，或一个 IPv6 **/64**。
- 计数每个请求为 O(1)，处于它自己的锁之下，在由两代组成的滑动一分钟内进行；带凭据的 S3 请求
  从不等待它。
- 最近一分钟见过的来源，只要表中少于 **2 × 10000** 个条目就会被计数（无论洪水持续多久，这是上界）。
  满表没见过的来源，计入其网络的溢出桶——其 **/48**（IPv6）或 **/24**（IPv4），各为速率的十倍——
  所以洪水耗尽的是它所来自网络的桶，而不是所有人的桶。同一 /24 之后的 IPv4 邻居（CGNAT、校园网）
  共用一个桶。
- ⛔ **每分钟超过 1024 个网络后，由一个共享桶服务其余来源**：拥有更多网络的攻击者会耗尽它，
  表中尚未见过的每个来源——**包括大约每小时续期一次的现有客户端**——都会被拒绝，直到这一分钟翻过去。
  这是此设计的限度。

## 在指向大对象之前值得了解的两个限制 {#two-limits-worth-knowing-before-pointing-it-at-something-large}

**`GetObject` 会把整个对象读入内存。** 驱动接口只提供
`ReadFile`，没有别的，没有 opener，也没有 reader，因此没有可用的
流式读取。256 MiB 的上限会返回 `EntityTooLarge`，而不是让
进程崩溃。

**`LastModified` 是纪元时间。** `filesystem.Stat` 携带 `Mode`、`Size` 和
`Inode`，完全没有修改时间。该字段在 S3
模式中不是可选的，因此必须发送一个值；纪元时间显然不是真实时间，
而 `time.Now()` 则会像是刚刚更改的文件，使每个同步
工具在每次运行时都复制所有内容。
