从 v0.39.0 起,文件的时间是其文件系统记录的时间,而不是请求发生的时刻。
这需要 `go-filesystems/interface` v0.6.0 的可选能力 `TimesReader`,驱动程序
可能具备,也可能不具备。

## 哪些共享报告真实时间 {#which-shares-report-real-times}

| 共享 | 真实时间 |
|---|---|
| **目录**(主机) | 是:访问、修改、变更,以及主机保存时的创建时间,精确到纳秒 |
| **FAT 镜像** | 是,按 FAT 的精度:修改 2 秒,访问 1 天,创建 10 毫秒;没有变更时间 |
| **exFAT 镜像**(自 v0.40.0 起) | 是:创建和修改 10 毫秒,访问 2 秒;没有变更时间 |
| **NTFS 镜像**(自 v0.40.0 起) | 是:创建、修改、变更和访问,100 纳秒 |
| **ext4 镜像**(自 v0.40.0 起) | 是:访问、修改和变更精确到 1 纳秒(ext2/ext3 的 128 字节 inode 为 1 秒);仅当 inode 足够大时才有创建时间 |
| **HFS+ 镜像**(自 v0.40.0 起) | 是:创建、修改、变更和访问,1 秒 |
| 其他镜像类型 | 与以前一样应答 |
| 以本人身份提供的共享(`remote` 工作进程) | 是,当工作进程的目录是主机目录时:时间会越过工作进程的边界 |

时间按格式精度与协议精度中**较粗**的一个进行比较:SFTP 传送整秒,WebDAV 的
`getlastmodified` 也是整秒,SMB 为 100 ns,NFS 为 1 ns。

## 时间未记录时 {#when-a-time-is-not-recorded}

| 协议 | 发送的内容 |
|---|---|
| **SMB** | 0,即“未指定”。没有该能力的驱动程序仍然回答当前时间。 |
| **NFS** | 缺失的访问时间或变更时间变为修改时间;缺失的修改时间变为服务器的启动时间。 |
| **SFTP** | 缺失的修改时间会清除 `ACMODTIME` 标志:客户端看到的是没有时间,而不是错误的时间。 |
| **WebDAV** | `creationdate` 是创建时间;未记录的时间不会出现在应答中。 |

## 客户端通过 SMB 设置的时间 {#setting-times}

自 v0.41.0 起(`go-filesystems/smb` v0.10.0,
go-filesystems/smb#45),客户端通过 SMB 设置的访问时间和修改时间
(`SET_INFO`,`touch`、`robocopy /COPY:T` 以及资源管理器中的复制都会这样做)
会应用到**目录**共享中的文件上。值为 0 的时间保持不变;-1 冻结该时间,-2 恢复,
按每个打开的句柄生效。

无法存储的时间**默认被忽略**:请求成功,该字段被丢弃,与 Samba 的做法一致,
这样保留时间的复制就不会失败。这包括创建时间、单独发送的变更时间,以及
无法设置时间的驱动程序上的任何时间。fileshare 没有为此提供设置:所有共享都
使用默认值。

### 选择如何处理:`unstorable_times` {#unstorable-times}

自 v0.42.0 起，共享可以用 `unstorable_times` 指定如何处理这样的时间
（即 `go-filesystems/smb` 的 `UnstorableTimes` 选项）：

```hcl
share "attic" {
  directory        = "/srv/attic"
  unstorable_times = "refuse"   # "ignore"（默认）、"refuse" 或 "log"
}
```

| 取值 | 客户端收到的响应 | 保留的内容 |
|---|---|---|
| `ignore`（未设置时同样如此） | 成功 | 该字段被丢弃，与 Samba 一致 |
| `refuse` | `STATUS_NOT_SUPPORTED`，这样备份工具就不会误以为时间已被保留 | 该请求中的任何内容都不会被应用 |
| `log` | 成功 | 该字段被丢弃，并且每个请求写一行，写明共享、路径和字段，输出到服务器自己写日志的地方 |

其他任何取值都会在读取配置时被拒绝，错误信息会指出共享名和这三个取值。
该设置属于 SMB：`protocols` 不含 SMB 的共享若设置它，会被拒绝。
没有服务器级的默认值，需在每个共享上分别设置。通过管理 API 创建的共享使用 `ignore`。
