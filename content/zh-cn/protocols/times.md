从 v0.39.0 起,文件的时间是其文件系统记录的时间,而不是请求发生的时刻。
这需要 `go-filesystems/interface` v0.6.0 的可选能力 `TimesReader`,驱动程序
可能具备,也可能不具备。

## 哪些共享报告真实时间 {#which-shares-report-real-times}

| 共享 | 真实时间 |
|---|---|
| **目录**(主机) | 是:访问、修改、变更,以及主机保存时的创建时间,精确到纳秒 |
| **FAT 镜像** | 是,按 FAT 的精度:修改 2 秒,访问 1 天,创建 10 毫秒;没有变更时间 |
| **exFAT 镜像**(自 v0.40.0 起) | 是:创建和修改 10 毫秒,访问 2 秒;没有变更时间 |
| **NTFS 镜像**(自 v0.40.0 起) | 是:创建、修改、变更和访问,100 纳秒 |
| **ext4 镜像**(自 v0.40.0 起) | 是:访问、修改和变更精确到 1 纳秒(ext2/ext3 的 128 字节 inode 为 1 秒);仅当 inode 足够大时才有创建时间 |
| **HFS+ 镜像**(自 v0.40.0 起) | 是:创建、修改、变更和访问,1 秒 |
| 其他镜像类型 | 与以前一样应答 |
| 以本人身份提供的共享(`remote` 工作进程) | 是,当工作进程的目录是主机目录时:时间会越过工作进程的边界 |

时间按格式精度与协议精度中**较粗**的一个进行比较:SFTP 传送整秒,WebDAV 的
`getlastmodified` 也是整秒,SMB 为 100 ns,NFS 为 1 ns。

## 时间未记录时 {#when-a-time-is-not-recorded}

| 协议 | 发送的内容 |
|---|---|
| **SMB** | 0,即“未指定”。没有该能力的驱动程序仍然回答当前时间。 |
| **NFS** | 缺失的访问时间或变更时间变为修改时间;缺失的修改时间变为服务器的启动时间。 |
| **SFTP** | 缺失的修改时间会清除 `ACMODTIME` 标志:客户端看到的是没有时间,而不是错误的时间。 |
| **WebDAV** | `creationdate` 是创建时间;未记录的时间不会出现在应答中。 |

## 客户端通过 SMB 设置的时间 {#setting-times}

自 v0.41.0 起(`go-filesystems/smb` v0.10.0,
go-filesystems/smb#45),客户端通过 SMB 设置的访问时间和修改时间
(`SET_INFO`,`touch`、`robocopy /COPY:T` 以及资源管理器中的复制都会这样做)
会应用到**目录**共享中的文件上。值为 0 的时间保持不变;-1 冻结该时间,-2 恢复,
按每个打开的句柄生效。

无法存储的时间**默认被忽略**:请求成功,该字段被丢弃,与 Samba 的做法一致,
这样保留时间的复制就不会失败。这包括创建时间、单独发送的变更时间,以及
无法设置时间的驱动程序上的任何时间。fileshare 没有为此提供设置:所有共享都
使用默认值。

### 选择如何处理:`unstorable_times` {#unstorable-times}

自 v0.42.0 起，共享可以用 `unstorable_times` 指定如何处理这样的时间
（即 `go-filesystems/smb` 的 `UnstorableTimes` 选项）：

```hcl
share "attic" {
  directory        = "/srv/attic"
  unstorable_times = "refuse"   # "ignore"（默认）、"refuse" 或 "log"
}
```

| 取值 | 客户端收到的响应 | 保留的内容 |
|---|---|---|
| `ignore`（未设置时同样如此） | 成功 | 该字段被丢弃，与 Samba 一致 |
| `refuse` | `STATUS_NOT_SUPPORTED`，这样备份工具就不会误以为时间已被保留 | 该请求中的任何内容都不会被应用 |
| `log` | 成功 | 该字段被丢弃，并且每个请求写一行，写明共享、路径和字段，输出到服务器自己写日志的地方 |

其他任何取值都会在读取配置时被拒绝，错误信息会指出共享名和这三个取值。
该设置属于 SMB：`protocols` 不含 SMB 的共享若设置它，会被拒绝。
没有服务器级的默认值，需在每个共享上分别设置。通过管理 API 创建的共享使用 `ignore`。

### 什么时候时间无法存储 {#when-unstorable}

请求按字段逐个判断，只要有一个字段无法存储就够了：`refuse` 会拒绝整个请求，
`log` 会写一行。在以下情况下，时间无法存储：

1. **CreationTime** 被设置为与驱动程序所报告的值不同的值（或驱动程序没有报告
   任何值）。没有办法设置创建时间。与所报告的值相同的值会被接受：没有需要改变
   的内容。
2. **ChangeTime** **单独**发送，且其值与所报告的值不同。与访问时间或修改时间
   一起发送时，如果驱动程序能设置时间，则会被接受，因为设置时间会把变更时间
   刷新为“现在”。
3. 在驱动程序无法设置时间（没有 `Chtimes`）的共享上设置**访问时间或修改时间**：
   任何真实的值都算，无论是否与当前值相同。

有三件事不由该策略决定。值为 0（保持）、-1（冻结）或 -2（恢复）的时间永远不会
被视为无法存储。在能设置时间但无法报告时间的驱动程序上，-1 在所有模式下始终是
`STATUS_NOT_SUPPORTED`：这是缺少某项能力，而不是被丢弃的字段（ufs、btrfs、xfs 和 zfs 镜像属于这种情况）。而对**只读**共享（`read_only = true`、设备、选择了分区的
共享、没有写权限的人）的请求，在所有这些之前、在所有模式下都会得到
`STATUS_MEDIA_WRITE_PROTECTED`。

共享能存储什么取决于它的驱动程序（以本版本锁定的版本为准）：

| 共享 | CreationTime | 单独的 ChangeTime | 访问时间或修改时间 |
|---|---|---|---|
| **目录**（主机） | 除非等于所报告的创建时间，否则无法存储 | 除非等于所报告的值，否则无法存储 | 可存储（一起发送的 ChangeTime 会被接受） |
| **镜像，驱动程序带 `Chtimes`**：ext4、ufs、btrfs、xfs、zfs | 除非等于所报告的值，否则无法存储（只有 ext4 会报告；其他的始终无法存储） | 同左 | 可存储（一起发送的 ChangeTime 会被接受） |
| **镜像，FAT 或 exFAT**（自 v0.43.0 起） | 除非等于所报告的值，否则无法存储（两者都会报告） | 同左 | 按格式的精度存储：FAT 的修改时间为 2 秒（向下取整），访问时间只保留日期；exFAT 的修改时间为 10 毫秒，访问时间为 2 秒（一起发送的 ChangeTime 会被接受） |
| **镜像，HFS+**（自 v0.44.0 起） | 除非等于所报告的值，否则无法存储（它会报告） | 同左 | 精确到秒存储（一起发送的 ChangeTime 会被接受），仅当共享设置了 `hfsplus_writable_max` 时（自 v0.45.1 起，默认只读），且日志未使该共享变为[只读]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}}) |
| **镜像，驱动程序不带 `Chtimes`**：NTFS、APFS、ISO 9660、SquashFS | 同左（NTFS 会报告；其他的从不报告） | 同左；与访问时间或修改时间一起发送时**同样如此** | **始终无法存储** |

带 `Chtimes` 的驱动程序有 osfs（`osfs.go:383`）、ext4（`metadata.go:93`）、ufs
（`metadata.go:63`）、btrfs（`fs.go:382`）、xfs（`fs.go:521`）和 zfs
（`metadata.go:94`），自 v0.43.0 起还有 fat32 v0.13.0 和 exFAT v0.6.0（完整的
`MetadataSetter`：由于 FAT 没有权限位和所有者，它们的 `Chmod` 与 `Chown` 返回“不支持”），
因此 FAT 或 exFAT 镜像共享上的 `touch -d` 和 `cp -p` 会被存储；其余都没有。
HFS+ 也有：hfsplus v0.8.0 实现了 `Chtimes`、`Chmod` 和 `Chown`，
自 v0.44.0（hfsplus v0.9.0）起，提供的 HFS+ 镜像可以以可写方式打开，因此通过 SMB 设置的时间会被存储，但自 v0.45.1 起仅当共享设置了
`hfsplus_writable_max` 时才如此（默认只读）。
日志中含有未完成事务的镜像则改为只读打开，不存储任何内容
（参见 [HFS+ 镜像可写]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}})）。在 v0.42.0 之前，fileshare 放在每个镜像驱动程序前面的锁
隐藏了 `Chtimes`，因此包括 ext4 在内的所有镜像都会丢弃客户端的访问时间和修改时间；
自 v0.42.0 起，只有驱动程序本身带有 `Chtimes` 时，锁才会传递它。NTFS 镜像由只读驱动程序
读取，因此无论策略如何都不会存储任何内容；策略只决定告诉客户端什么。

哪些客户端触发哪种情况：Windows 资源管理器和 `robocopy /COPY:T` 会发送
CreationTime，除非它没有变化，否则任何类型的共享都无法保留；Linux 的 `touch -d`
和 `cp -p` 只发送访问时间和修改时间（内核客户端还会附带一个“现在”的 ChangeTime），
目录和带 `Chtimes` 的驱动程序可以存储它们，不带的则不能。
