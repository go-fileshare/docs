v0.39.0 から、ファイルの時刻はリクエスト時刻ではなく、そのファイルシステムが
記録した時刻になります。これには `go-filesystems/interface` v0.6.0 の任意機能
`TimesReader` が必要で、ドライバーが持っている場合と持っていない場合があります。

## 実際の時刻を返す共有 {#which-shares-report-real-times}

| 共有 | 実際の時刻 |
|---|---|
| **ディレクトリ**(ホスト) | はい: アクセス、更新、変更、ホストが保持していれば作成時刻。ナノ秒単位 |
| **FAT イメージ** | はい。FAT の分解能で: 更新 2 秒、アクセス 1 日、作成 10 ミリ秒。変更時刻はありません |
| **exFAT イメージ**(v0.40.0 以降) | はい: 作成と更新 10 ミリ秒、アクセス 2 秒。変更時刻はありません |
| **NTFS イメージ**(v0.40.0 以降) | はい: 作成、更新、変更、アクセス。100 ナノ秒 |
| **ext4 イメージ**(v0.40.0 以降) | はい: アクセス、更新、変更は 1 ナノ秒(ext2/ext3 の 128 バイト inode では 1 秒)。作成時刻は inode が十分大きい場合のみ |
| **HFS+ イメージ**(v0.40.0 以降) | はい: 作成、更新、変更、アクセス。1 秒 |
| その他のイメージ形式 | 従来どおり応答します |
| 本人として提供される共有(`remote` ワーカー) | はい。ワーカーのディレクトリがホストのディレクトリの場合: 時刻はワーカーの境界を越えます |

時刻は、形式の分解能とプロトコルの分解能の**粗い方**で比較されます。SFTP は
整数秒、WebDAV の `getlastmodified` も整数秒、SMB は 100 ns、NFS は 1 ns です。

## 時刻が記録されていないとき {#when-a-time-is-not-recorded}

| プロトコル | 送られる値 |
|---|---|
| **SMB** | 0(「未指定」)。この機能を持たないドライバーは、従来どおり現在時刻を返します。 |
| **NFS** | アクセス時刻または変更時刻がない場合は更新時刻になり、更新時刻がない場合はサーバーの起動時刻になります。 |
| **SFTP** | 更新時刻がない場合は `ACMODTIME` フラグを消します。誤った時刻ではなく、時刻なしとして見えます。 |
| **WebDAV** | `creationdate` は作成時刻です。記録されていない時刻は応答に含まれません。 |

## SMB でクライアントが設定する時刻 {#setting-times}

v0.41.0 から(`go-filesystems/smb` v0.10.0、
go-filesystems/smb#45)、クライアントが SMB で設定したアクセス時刻と更新時刻
(`SET_INFO`。`touch`、`robocopy /COPY:T`、エクスプローラーでのコピーが行う操作)
が、**ディレクトリ**共有のファイルに反映されます。値が 0 の時刻はそのまま
です。-1 はその時刻を固定し、-2 で再開します(開いているハンドルごと)。

保存できない時刻は**既定では無視されます**。要求は成功し、そのフィールドだけが
捨てられます(Samba と同じ動作で、時刻を保つコピーが失敗しないようにするため
です)。対象は、作成時刻、単独で送られた変更時刻、時刻を設定できないドライバー
上のすべての時刻です。fileshare にはこのための設定はなく、すべての共有が既定を
使います。

### 動作を選ぶ:`unstorable_times` {#unstorable-times}

v0.42.0 から、共有ごとに `unstorable_times` でこの種の時刻の扱いを指定できます
(`go-filesystems/smb` の `UnstorableTimes` オプション)。

```hcl
share "attic" {
  directory        = "/srv/attic"
  unstorable_times = "refuse"   # "ignore"(既定)、"refuse"、"log"
}
```

| 値 | クライアントに返る応答 | 保持されるもの |
|---|---|---|
| `ignore`(設定がない場合も) | 成功 | そのフィールドは捨てられる(Samba と同じ) |
| `refuse` | `STATUS_NOT_SUPPORTED`。バックアップツールが時刻を保持できたと誤解しないようにするため | その要求の内容は何も適用されない |
| `log` | 成功 | そのフィールドは捨てられ、要求ごとに共有名、パス、フィールドを記した 1 行が、サーバー自身の出力先に書かれる |

これ以外の値は、設定の読み込み時に、共有名と 3 つの値を示すエラーで拒否されます。
この設定は SMB のものです。`protocols` が SMB を含まない共有でこれを設定すると
拒否されます。サーバー全体の既定値はなく、共有ごとに指定します。管理 API で作成した
共有は `ignore` になります。

### 時刻が保存できない場合 {#when-unstorable}

要求はフィールドごとに判断され、保存できないフィールドが 1 つあれば十分です。
`refuse` は要求全体を拒否し、`log` は 1 行を書きます。次の場合、時刻は保存できません。

1. **CreationTime** が、ドライバーが報告する値と異なる値に設定された場合
   (またはドライバーが何も報告しない場合)。作成時刻を設定する手段はありません。
   報告された値と同じ値は受理されます(変更するものがないため)。
2. **ChangeTime** が**単独で**送られ、その値が報告された値と異なる場合。
   アクセス時刻または更新時刻と一緒に送られた場合は、ドライバーが時刻を設定
   できるなら受理されます。時刻の設定によって変更時刻が「現在」に更新される
   ためです。
3. 時刻を設定できないドライバー(`Chtimes` なし)の共有での**アクセス時刻または
   更新時刻**。現在の値と同じかどうかにかかわらず、実際の値はすべて対象です。

次の 3 点はポリシーでは決まりません。0(保持)、-1(固定)、-2(再開)の時刻は
保存不可になることはありません。時刻を設定できるが報告できないドライバーでの
-1 は、どのモードでも常に `STATUS_NOT_SUPPORTED` です。これは機能の欠如であり、
捨てられたフィールドではありません(ufs、btrfs、xfs、zfs のイメージが該当します)。
また、**読み取り専用**の共有(`read_only = true`、デバイス、
パーティションを選んだ共有、書き込み権のない人)への要求は、これらより前に、
どのモードでも `STATUS_MEDIA_WRITE_PROTECTED` で応答されます。

共有が何を保存できるかはドライバーによります(このリリースが固定しているバージョンで)。

| 共有 | CreationTime | ChangeTime 単独 | アクセス時刻または更新時刻 |
|---|---|---|---|
| **ディレクトリ**(ホスト) | 報告された作成時刻と同じでない限り保存不可 | 報告された値と同じでない限り保存不可 | 保存される(一緒に送られた ChangeTime は受理) |
| **イメージ、`Chtimes` を持つドライバー**:ext4、ufs、btrfs、xfs、zfs | 報告された値と同じでない限り保存不可(報告するのは ext4 のみ。他は常に不可) | 同上 | 保存される(一緒に送られた ChangeTime は受理) |
| **イメージ、FAT または exFAT**(v0.43.0 以降) | 報告された値と同じでない限り保存不可(どちらも報告する) | 同上 | 形式の精度で保存される:FAT は更新時刻が 2 秒(切り捨て)、アクセス時刻は日付のみ。exFAT は更新時刻が 10 ms、アクセス時刻が 2 秒(一緒に送られた ChangeTime は受理) |
| **イメージ、HFS+**(v0.44.0 以降) | 報告された値と同じでない限り保存不可(報告する) | 同上 | 1 秒単位で保存される(一緒に送られた ChangeTime は受理)。ジャーナルにより共有が[読み取り専用]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}})になった場合を除く |
| **イメージ、`Chtimes` を持たないドライバー**:NTFS、APFS、ISO 9660、SquashFS | 同上(NTFS は報告し、他は報告しない) | 同上。アクセス時刻または更新時刻と一緒でも**同様** | **常に保存不可** |

`Chtimes` を持つドライバーは osfs(`osfs.go:383`)、ext4(`metadata.go:93`)、ufs
(`metadata.go:63`)、btrfs(`fs.go:382`)、xfs(`fs.go:521`)、zfs(`metadata.go:94`)、
および v0.43.0 以降は fat32 v0.13.0 と exFAT v0.6.0 です(完全な `MetadataSetter`。
FAT にはモードビットも所有者もないため、これらの `Chmod` と `Chown` は「未対応」を返します)。
そのため FAT・exFAT イメージの共有での `touch -d` と `cp -p` は保存されます。他にはありません。
HFS+ にもあります。hfsplus v0.8.0 は `Chtimes`、`Chmod`、`Chown` を実装しており、
v0.44.0(hfsplus v0.9.0)以降、提供される HFS+ イメージは書き込み可能で開かれるため、
SMB で設定した時刻は保存されます。ジャーナルにトランザクションが残っているイメージは
代わりに読み取り専用で開かれ、何も保存されません
([HFS+ イメージは書き込み可能]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}})を参照)。v0.42.0 より前は、fileshare がすべてのイメージドライバーの前に
置くロックが `Chtimes` を隠していたため、ext4 を含むすべてのイメージがクライアントの
アクセス時刻と更新時刻を捨てていました。v0.42.0 からは、ドライバーが持つ場合にだけ
`Chtimes` を通します。NTFS イメージは読み取り専用のドライバーで読まれるため、
ポリシーにかかわらず何も保存されません。ポリシーが決めるのは、クライアントに何を
返すかだけです。

どのクライアントがどの場合に該当するか:Windows のエクスプローラーと
`robocopy /COPY:T` は CreationTime を送ります。これは、変更がなければ別ですが、
どの種類の共有でも保持できません。Linux の `touch -d` と `cp -p` はアクセス時刻と
更新時刻だけを送ります(カーネルのクライアントは「現在」の ChangeTime を加えます)。
これらはディレクトリと `Chtimes` を持つドライバーでは保存され、持たないドライバーでは
保存されません。
