```hcl
serve "s3" { addr = "0.0.0.0:9000" }
```

v0.9.0 以降は、`tls = true` と [`tls` ブロック]({{< relref "/security/tls.md" >}})を指定すれば HTTPS でも提供できます。

```hcl
serve "s3" {
  addr = "0.0.0.0:9000"
  tls  = true
}
```

5 つ目のプロトコルであり、オブジェクトストレージを話すもの(バックアップツール、データパイプライン、
`rclone`、ブラウザーの `fetch()`)なら何からでもイメージに到達できるようにするものです。
**何もマウントしません。**

```
GET /                      the shares this person may use, as buckets
GET /photos?list-type=2    the files in that share, as keys
GET /photos/holiday.jpg    the file itself, Range and all
```

## 共有はバケット {#a-share-is-a-bucket}

**SFTP が使うのと同じユーザーごとのツリー**、つまりトップレベルがその人の利用できる共有である
ファイルシステム上で提供されます。そのため、alice が利用できない共有は alice に見えるバケットになりません。
アクセスルールは、2 つ目のプロトコルにコピーされるのではなく、1 か所で適用されます。

{{< callout type="info" >}}
**共有内のディレクトリはプレフィックスであり、オブジェクトではない**

これは S3 クライアントがすでに前提としていることです。区切り文字で終わるプレフィックスを
フォルダーとして表示します。ディレクトリへの `GET` は `NoSuchKey` を返します。200 を返すと、
クライアントはフォルダーのバイト列を取得できると考えてしまうためです。
{{< /callout >}}

## アクセスキーはユーザー、シークレットキーはそのパスワード {#an-access-key-is-a-user-the-secret-key-is-their-password}

```sh
export AWS_ACCESS_KEY_ID=alice
export AWS_SECRET_ACCESS_KEY=$(cat alice.pw)
aws --endpoint-url http://attic.example.org:9000 s3 ls
```

SigV4 は、シークレットから HMAC を計算することでその所持を証明します。NTLMv2 とまったく同様に、
パスワードはネットワークを流れません。

{{< callout type="error" >}}
**そのため、ディレクトリはパスワードを確認するだけでなく、保持していなければなりません**

パスワードを*検証*することしかできないソース(LDAP バインド、bcrypt の列)は、WebDAV には
応答できますが、S3 には**応答できません**。

NT ハッシュでも不十分です。それは SMB が計算の元にできる MD4 ですが、そこから HMAC は計算できません。
**NT ハッシュしか持たない ID は SMB には対応しても S3 には対応しません。** 近い関係にあっても、
同じ答えではありません。[`check`]({{< relref "/configuration/check.md" >}})はその列を表示します。
{{< /callout >}}

⛔ プログラムのどこにも `Password()` アクセサーはありません。パスワードには `Identity.Derive` を通じてのみ
到達でき、これは導出処理を受け取ってその結果を返します。S3 では、SigV4 の鍵スケジュールが
go-filesystems/s3 にあるため、導出は恒等変換です。シークレットは、その 1 人のユーザーのための署名検査にのみ
渡され、ほかのどこにも渡りません。

## 提供されるもの {#what-is-served}

`ListBuckets`、`HeadBucket`、プレフィックス、区切り文字、max-keys、継続を指定できる `ListObjectsV2`、
`HeadObject`、`Range` 付きの `GetObject`。SigV4 は、ヘッダーと署名付き URL の両方の形式に対応します。

オブジェクト API 自体は
[`go-filesystems/s3`](https://github.com/go-filesystems/s3) です。

## 拒否されるものと、その理由 {#what-is-refused-and-why}

{{< callout type="warning" >}}
**書き込みは 403 で応答されます**

`PUT`、`POST`、`DELETE` は `AccessDenied`("this export is read-only")で拒否されます。
fileshare が S3 サーバーを読み取り専用にしているのは、読み取りしか許されていない人の共有は
SFTP と同じ場所で拒否しなければならず、それがまだ組み込まれていないためです。このリリースが
ビルドの土台としている go-filesystems/s3 v0.3.0 は、いずれにせよすべての書き込みを拒否します。
中途半端に書かれたオブジェクトよりも、拒否するほうが安全です。
{{< /callout >}}

{{< callout type="warning" >}}
**ベアラートークンはここでは受け付けられません**

[OIDC]({{< relref "/protocols/webdav.md" >}})が機能するのは WebDAV だけです。S3 は SigV4 署名、つまり
リクエストに対する HMAC で認証し、ベアラートークンを収められるフィールドがありません。

方法は STS の `AssumeRoleWithWebIdentity` で、OIDC トークンを一時的な認証情報と交換し、
クライアントがそれで署名します。v0.50.0 からこのリスナーで提供されます。[下記](#sts)を参照してください。
{{< /callout >}}

マルチパートアップロード、バージョニング、ACL、ポリシー、ライフサイクルルール、レプリケーション、
タグ付けは実装されていません。これらのいずれかの設定とマルチパートアップロードの開始は書き込みであり、
ほかの書き込みと同様に `AccessDenied` で応答されます。これらのいずれかを求める `GET`
(`?versioning`、`?acl`、`?tagging` など)は区別されません。クエリは無視され、バケットの一覧または
オブジェクトが返されます。`NotImplemented` が返されるのは、`list-type=2` 以外の一覧、`/` に対する
`GET` 以外のメソッド、ここで使われる操作のいずれにも該当しないメソッドです。

## 一時的な認証情報: STS `AssumeRoleWithWebIdentity` {#sts}

v0.50.0 から、S3 リスナーは AWS STS API(`AssumeRoleWithWebIdentity`、バージョン 2011-06-15)にも
応答します。[`oidc` ブロック]({{< relref "/protocols/webdav.md" >}})のプロバイダーのトークンが、**失効する**アクセスキー、
シークレットキー、セッショントークンと交換されます。`aws`、`rclone`、AWS SDK は AWS に対するのと
同じように話し、誰もパスワードを持ちません。

```hcl
oidc {
  issuer   = "https://login.example.org"
  audience = "fileshare"
}

serve "s3" {
  addr             = "0.0.0.0:9000"
  tls              = true
  sts              = true      # Action=AssumeRoleWithWebIdentity の POST /
  sts_duration     = "1h"      # 既定値。15m から 12h
  sts_max_duration = "4h"      # DurationSeconds が求められる上限。既定は sts_duration
  static_keys      = false     # 「アクセスキーはユーザー」をやめる: 一時的な認証情報だけが署名する
}
```

- **トークン**は、`oidc` ブロックのプロバイダーが発行するアクセストークン(`typ` が `at+jwt`)で、
  そのブロックの issuer と audience 向けです。2 つ目のプロバイダー設定はありません。人のトークン
  でも機械のトークンでも構いません。秘密鍵で認証するクライアント(`private_key_jwt`)に対する
  go-authn/bridge の `client_credentials` トークンは `sub` = クライアント ID で、それがここでの名前です。
- ⛔ **WebDAV のトークンと同じ規則を通ります。** ここのどのソースも知らない名前の有効なトークンは、
  `trust_all = true` か、共有の `oidc:` 規則がその名前を挙げていない限り拒否されます
  (`allow = ["oidc:user:winpc-17"]`)。何が見えるかは、その後で共有の規則が決めます。
- **応答**は `AccessKeyId`(`ASIA…`)、`SecretAccessKey`、`SessionToken`、`Expiration` です。
  リクエストはそれで署名され、セッショントークンを `x-amz-security-token` に載せます(**署名対象**)。
  ランダムで、メモリ上にのみあり、書き出されません。再起動で終わり、クライアントは再度求めます。
- ⛔ **有効期間 = min(要求した期間, トークンの残り)。** 認証情報は、それを得たトークンより長く
  生きることはありません(`sts_duration`、または `sts_max_duration` までの `DurationSeconds` は上限に
  すぎません)。残りが **6 分未満**のトークンは `ExpiredTokenException` で拒否されます。AWS SDK は
  `Expiration` の約 5 分前に更新するため、それより短い認証情報は直ちに、永遠に更新されてしまうからです。
  クライアントは交換のたびに新しいトークンを提示します。
- ⛔ **セッションはリクエストごとに判断されます。** 期限が切れます。セッショントークンはそのアクセス
  キーに結び付けられています。トークン発行後にプロバイダーがその人を失効させると
  ([共有シグナル]({{< relref "/security/shared-signals.md" >}}))、終わります。設定がその名前を
  受け入れなくなった場合も終わります。
- `Policy`、`PolicyArns`、2 つ目の `WebIdentityToken` は拒否され、パラメーターは POST ボディに置きます。
  URL には置きません。
- **`static_keys = false`** は、「アクセスキーはユーザー、シークレットキーはそのパスワード」の方式を
  オフにします。`sts = true` が必要で、なければ設定は読み込み時に拒否されます。誰も署名できない
  リスナーは設定済みに見えてしまうからです。ループバック以外のアドレスでは、`sts` に `tls = true`、
  または TLS を手前で終端する場合は `plaintext = true` が必要です。

### 無人のマシンでは: awscred

[`awscred`](https://github.com/go-authn/awscred) v0.1.0 は、秘密鍵を持ちパスワードを持たない
マシンのための AWS `credential_process` です。`private_key_jwt` に署名し、go-authn/bridge から
トークンを得て、このエンドポイントを呼び、SDK が読む形で認証情報を出力します。SDK は
`Expiration` の前に再実行します。

```ini
[profile fileshare]
credential_process = awscred --issuer https://login.example.org --client winpc-17 --key /etc/awscred/winpc-17.pem --sts https://s3.example.org
```

⛔ Unix では、`awscred` はグループまたは他者が読める鍵ファイルを拒否します(`chmod 600`)。
Windows ではファイルモードは意味を持ちません。鍵はサービスアカウントのプロファイル、または
そのアカウントだけを許可する ACL のディレクトリに置いてください。Windows の CNG ストアや TPM
の鍵はまだサポートされていません。

### プロキシの背後では: `trusted_proxies`

`plaintext = true` が想定するプロキシの背後では、すべてのクライアントが下のレート制限にとって
1 つのソースになります。`s3` の serve ブロックでプロキシを指定します。

```hcl
serve "s3" {
  addr            = "127.0.0.1:9000"
  plaintext       = true
  sts             = true
  trusted_proxies = ["10.0.0.2", "10.0.1.0/29"]
}
```

信頼されたプロキシ**から**届いたリクエストだけが、そのクライアントについて信じられます。
`X-Forwarded-For` の右端の、それ自身が信頼されたプロキシではないホップを使います。それ以外からは
ヘッダーは無視されます。

{{< callout type="warning" >}}
**リストにはプロキシだけを挙げてください**

1 ホストより広いプレフィックス(`/24`、IPv6 の `/64`)は受け付けられ(プロキシのプール、`/29` は
正当です)、起動時に警告が出力されます。その中のアドレスを持てるクライアントは、自分の
`X-Forwarded-For` を、したがって数えられるバケットを自分で選べます。
{{< /callout >}}

### 制限

- **名前あたり 16 セッション**: 同じ名前の最も古いものから消え、他の名前のセッションは残ります
  (全体で 20000)。
- **ソースアドレスあたり毎分 60 リクエスト**。応答は `429 Throttling` です。すべてのリクエストは、
  有効かどうかにかかわらず、トークンが検証される前に数えられます。ソースは IPv4 アドレス、または
  IPv6 の **/64** です。
- 数えるのはリクエストあたり O(1) で、専用のロックの下、2 世代からなる滑る 1 分で行われます。
  認証情報付きの S3 リクエストがそれを待つことはありません。
- 直近 1 分に見たソースは、テーブルが **2 × 10000** 未満のエントリを保持している間は数えられます
  (洪水がどれだけ続いても、これが上限です)。満杯のテーブルが見ていないソースは、そのネットワークの
  オーバーフローバケット(**/48**(IPv6)または **/24**(IPv4)、それぞれレートの 10 倍)で数えられるので、
  洪水は、それが来たネットワークのバケットを使い切るだけで、全員のものは使い切りません。1 つの
  /24 の背後の IPv4 の隣人(CGNAT、キャンパス)は 1 つのバケットを共有します。
- ⛔ **毎分 1024 ネットワークを超えると、1 つの共有バケットが残りを受け持ちます。** それより多くの
  ネットワークを持つ攻撃者はそれを使い切り、テーブルがまだ見ていないソースはすべて、
  **約 1 時間ごとに更新する既存のクライアントも含めて**、分が変わるまで拒否されます。これがこの
  設計の限界です。

## 大きなものに向ける前に知っておくべき 2 つの制限 {#two-limits-worth-knowing-before-pointing-it-at-something-large}

**`GetObject` はオブジェクト全体をメモリに読み込みます。** ドライバーインターフェースが提供するのは
`ReadFile` だけで、オープナーもリーダーもないため、使えるストリーミング読み取りがありません。
上限の 256 MiB を超えると、プロセスを落とす代わりに `EntityTooLarge` で応答します。

**`LastModified` はエポックです。** `filesystem.Stat` が持つのは `Mode`、`Size`、`Inode` で、
更新時刻はまったくありません。S3 のスキーマではこのフィールドは省略できないため、何かを送る必要があります。
エポックは明らかに実際の時刻ではありません。`time.Now()` では、ファイルがたった今変わったように見え、
どの同期ツールも毎回すべてをコピーしてしまいます。
