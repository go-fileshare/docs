```hcl
serve "s3" { addr = "0.0.0.0:9000" }
```

v0.9.0 以降は、`tls = true` と [`tls` ブロック]({{< relref "/security/tls.md" >}})を指定すれば HTTPS でも提供できます。

```hcl
serve "s3" {
  addr = "0.0.0.0:9000"
  tls  = true
}
```

5 つ目のプロトコルであり、オブジェクトストレージを話すもの(バックアップツール、データパイプライン、
`rclone`、ブラウザーの `fetch()`)なら何からでもイメージに到達できるようにするものです。
**何もマウントしません。**

```
GET /                      the shares this person may use, as buckets
GET /photos?list-type=2    the files in that share, as keys
GET /photos/holiday.jpg    the file itself, Range and all
```

## 共有はバケット {#a-share-is-a-bucket}

**SFTP が使うのと同じユーザーごとのツリー**、つまりトップレベルがその人の利用できる共有である
ファイルシステム上で提供されます。そのため、alice が利用できない共有は alice に見えるバケットになりません。
アクセスルールは、2 つ目のプロトコルにコピーされるのではなく、1 か所で適用されます。

{{< callout type="info" >}}
**共有内のディレクトリはプレフィックスであり、オブジェクトではない**

これは S3 クライアントがすでに前提としていることです。区切り文字で終わるプレフィックスを
フォルダーとして表示します。ディレクトリへの `GET` は `NoSuchKey` を返します。200 を返すと、
クライアントはフォルダーのバイト列を取得できると考えてしまうためです。
{{< /callout >}}

## アクセスキーはユーザー、シークレットキーはそのパスワード {#an-access-key-is-a-user-the-secret-key-is-their-password}

```sh
export AWS_ACCESS_KEY_ID=alice
export AWS_SECRET_ACCESS_KEY=$(cat alice.pw)
aws --endpoint-url http://attic.example.org:9000 s3 ls
```

SigV4 は、シークレットから HMAC を計算することでその所持を証明します。NTLMv2 とまったく同様に、
パスワードはネットワークを流れません。

{{< callout type="error" >}}
**そのため、ディレクトリはパスワードを確認するだけでなく、保持していなければなりません**

パスワードを*検証*することしかできないソース(LDAP バインド、bcrypt の列)は、WebDAV には
応答できますが、S3 には**応答できません**。

NT ハッシュでも不十分です。それは SMB が計算の元にできる MD4 ですが、そこから HMAC は計算できません。
**NT ハッシュしか持たない ID は SMB には対応しても S3 には対応しません。** 近い関係にあっても、
同じ答えではありません。[`check`]({{< relref "/configuration/check.md" >}})はその列を表示します。
{{< /callout >}}

⛔ プログラムのどこにも `Password()` アクセサーはありません。パスワードには `Identity.Derive` を通じてのみ
到達でき、これは導出処理を受け取ってその結果を返します。S3 では、SigV4 の鍵スケジュールが
go-filesystems/s3 にあるため、導出は恒等変換です。シークレットは、その 1 人のユーザーのための署名検査にのみ
渡され、ほかのどこにも渡りません。

## 提供されるもの {#what-is-served}

`ListBuckets`、`HeadBucket`、プレフィックス、区切り文字、max-keys、継続を指定できる `ListObjectsV2`、
`HeadObject`、`Range` 付きの `GetObject`。SigV4 は、ヘッダーと署名付き URL の両方の形式に対応します。

オブジェクト API 自体は
[`go-filesystems/s3`](https://github.com/go-filesystems/s3) です。

## 拒否されるものと、その理由 {#what-is-refused-and-why}

{{< callout type="warning" >}}
**書き込みは 403 で応答されます**

`PUT`、`POST`、`DELETE` は `AccessDenied`("this export is read-only")で拒否されます。
fileshare が S3 サーバーを読み取り専用にしているのは、読み取りしか許されていない人の共有は
SFTP と同じ場所で拒否しなければならず、それがまだ組み込まれていないためです。このリリースが
ビルドの土台としている go-filesystems/s3 v0.3.0 は、いずれにせよすべての書き込みを拒否します。
中途半端に書かれたオブジェクトよりも、拒否するほうが安全です。
{{< /callout >}}

{{< callout type="warning" >}}
**ベアラートークンはここでは受け付けられません**

[OIDC]({{< relref "/protocols/webdav.md" >}})が機能するのは WebDAV だけです。S3 は SigV4 署名、つまり
リクエストに対する HMAC で認証し、ベアラートークンを収められるフィールドがありません。

通常の方法は STS の `AssumeRoleWithWebIdentity` で、OIDC トークンを一時的な認証情報と交換し、
クライアントがそれで署名します。これは別の仕組みであり、**実装されていません**。
{{< /callout >}}

マルチパートアップロード、バージョニング、ACL、ポリシー、ライフサイクルルール、レプリケーション、
タグ付けは実装されていません。これらのいずれかの設定とマルチパートアップロードの開始は書き込みであり、
ほかの書き込みと同様に `AccessDenied` で応答されます。これらのいずれかを求める `GET`
(`?versioning`、`?acl`、`?tagging` など)は区別されません。クエリは無視され、バケットの一覧または
オブジェクトが返されます。`NotImplemented` が返されるのは、`list-type=2` 以外の一覧、`/` に対する
`GET` 以外のメソッド、ここで使われる操作のいずれにも該当しないメソッドです。

## 大きなものに向ける前に知っておくべき 2 つの制限 {#two-limits-worth-knowing-before-pointing-it-at-something-large}

**`GetObject` はオブジェクト全体をメモリに読み込みます。** ドライバーインターフェースが提供するのは
`ReadFile` だけで、オープナーもリーダーもないため、使えるストリーミング読み取りがありません。
上限の 256 MiB を超えると、プロセスを落とす代わりに `EntityTooLarge` で応答します。

**`LastModified` はエポックです。** `filesystem.Stat` が持つのは `Mode`、`Size`、`Inode` で、
更新時刻はまったくありません。S3 のスキーマではこのフィールドは省略できないため、何かを送る必要があります。
エポックは明らかに実際の時刻ではありません。`time.Now()` では、ファイルがたった今変わったように見え、
どの同期ツールも毎回すべてをコピーしてしまいます。
