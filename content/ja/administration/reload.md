```hcl
reload = "5m"   # and on SIGHUP, and on the admin API's ReloadDirectory
```

人は、他のものが変更するディレクトリから取得されます。たとえば go-authn/bridge は
アプリケーションパスワードをテーブルに書き込み、その人が無効化されるとその行を削除します。
再読み込みがなければ、サーバーは起動時にいた人にだけサービスを提供し続けます。
v0.10.0 以降は、次のタイミングで読み直します。

- `reload` の間隔ごと。**1 秒以上**の Go の duration を指定します。1 秒に何度もディレクトリを読むのは、
  誰かのデータベースへの負荷であり、サーバーが新しくなるわけではありません。
- **`SIGHUP`**(Unix)を受けたとき。
- [管理 API]({{< relref "/administration/_index.md" >}})の **`ReloadDirectory`** を呼んだとき。
  追加、削除、変更された人、新しい世代が始まったかどうか、そして人が読むべき注記
  (存在しなくなった、またはメンバーのいないグループ、共有が名指ししているのにディレクトリに
  いなくなった人)を応答します。

`reload` がない場合、ディレクトリは起動時、`SIGHUP` 時、`ReloadDirectory` 時にのみ読み込まれます。

再読み込みされるのは、`users` ブロック(SQL、LDAP)です。設定ファイルの `user` ブロックと
`group` ブロックは、それ自体が設定であり、起動時に読み込まれます。

## 再読み込みの動作は、何が変わったかによる {#what-a-reload-does-depends-on-what-changed}

境界線は**失効**に引かれています。

| 変更内容 | 動作 |
|---|---|
| **追加のみ**: どの共有の展開済みリストも変えない新しい人(新しいアプリケーションパスワード、共有が `oidc:` ルールで到達する人、またはまったく到達しない人) | SMB の稼働中のサーバーを含めて**その場で**追加され、**どの接続にも触れない**。bridge が一日中アプリケーションパスワードを作成しても、誰も邪魔されない。 |
| **何かが取り除かれた**: 人がいなくなった、認証情報が変わった、共有の展開済みリストが変わった | **新しい世代**となり、古い世代の接続は[管理上の変更]({{< relref "/administration/_index.md#a-change-is-a-new-generation" >}})とまったく同じように**閉じられる**。その人が削除された後も生き残るセッションを終わらせることが、再読み込みの存在理由である。 |
| **ディレクトリを読み取れない**: データベースに到達できない、クエリが失敗する | **何も変更されない**。障害でファイルサーバーを空にしてはならず、読み取りの失敗は「誰もいない」ように見えるため。 |

共有が名指ししているグループに新しく加わった人は、その共有を*変える*ので、その共有に対する
ほかの変更と同様に、新しい世代を経ます。SMB は共有のリストを起動時に固定するためです。

いなくなった人や、存在しなくなった、またはメンバーがいなくなったグループ(v0.29.1 以降は
区別されます)を名指しする共有は、起動時に拒否されるのとは違って、**その人を除いて**提供され
(安全な方向です)、その旨が伝えられます。拒否すれば古いリストが維持されてしまい、古いリストとは
取り上げたばかりのアクセス権だからです。

## 空のグループは「全員」ではない {#an-empty-group-is-not-everyone}

{{< callout type="error" >}}
**`@engineers` 向けに書かれた共有は、最後のエンジニアが去ると、誰にも提供されなくなります**

空の `allow` は「認証した誰でも」を意味します。そのため、共有が開放されているかどうかを決めるのは
現在の展開結果ではなく、**書かれた内容**です。グループ向けに書かれた共有は、そのグループが空に
なっても閉じたままです。そのような共有は SMB ではまったく提供されません。SMB では空の
`AllowUsers` が全員と解釈されてしまうからです。
{{< /callout >}}

## 監視 {#watching-it}

`fileshare_directory_reloads_total{result}` は、何も見つからなかった再読み込み(`unchanged`)、
その場で追加した再読み込み(`added`)、世代を開始した再読み込み(`swapped`)、ディレクトリを
読み取れなかった再読み込み(`failed`)を数えます。`fileshare_directory_people` は、直近の読み取りが
保持していた人数です。[ヘルスチェックとメトリクス]({{< relref "/administration/health.md" >}})を参照してください。

{{< callout type="info" >}}
**再読み込みが届かないもの**

トークンや証明書を通じて ID プロバイダーが身元を保証する人は、ディレクトリにいないため、
再読み込みの対象外です。**その人たち**を取り消すのは、
[失効リストと共有シグナル]({{< relref "/security/_index.md" >}})の役割です。
{{< /callout >}}
