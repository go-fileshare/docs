```hcl
serve "s3" { addr = "0.0.0.0:9000" }
```

O por HTTPS, desde la v0.9.0, con `tls = true` y un
[bloque `tls`]({{< relref "/security/tls.md" >}}):

```hcl
serve "s3" {
  addr = "0.0.0.0:9000"
  tls  = true
}
```

El quinto protocolo, y el que hace que una imagen sea accesible desde cualquier cosa
que hable almacenamiento de objetos: una herramienta de copias de seguridad, una
canalización de datos, `rclone`, el `fetch()` de un navegador. **No se monta nada.**

```
GET /                      the shares this person may use, as buckets
GET /photos?list-type=2    the files in that share, as keys
GET /photos/holiday.jpg    the file itself, Range and all
```

## Un recurso compartido es un bucket {#a-share-is-a-bucket}

Servido sobre el **mismo árbol por usuario que usa SFTP**: un sistema de archivos
cuyo nivel superior son los recursos compartidos que esa persona puede usar. Así, un
recurso compartido que alice no puede usar no es un bucket que alice pueda ver, y las
reglas de acceso se aplican en un solo lugar en vez de copiarse a un segundo
protocolo.

{{< callout type="info" >}}
**Un directorio dentro de un recurso compartido es un prefijo, no un objeto**

Que es lo que los clientes S3 ya creen: muestran como carpetas los prefijos
que terminan en el delimitador. Un `GET` de un directorio responde
`NoSuchKey`, porque responder 200 haría creer a un cliente que puede
descargar los bytes de una carpeta.
{{< /callout >}}

## Una clave de acceso es un usuario; la clave secreta es su contraseña {#an-access-key-is-a-user-the-secret-key-is-their-password}

```sh
export AWS_ACCESS_KEY_ID=alice
export AWS_SECRET_ACCESS_KEY=$(cat alice.pw)
aws --endpoint-url http://attic.example.org:9000 s3 ls
```

SigV4 prueba la posesión del secreto calculando un HMAC a partir de él: la contraseña
nunca cruza la red, exactamente como con NTLMv2.

{{< callout type="error" >}}
**Por eso el directorio debe GUARDAR la contraseña, y no solo comprobarla**

Un origen que solo puede *verificar* una contraseña —un bind LDAP, una
columna bcrypt— puede responder a WebDAV y **no puede** responder a S3.

Y tampoco sirve un hash NT: es el MD4 con el que SMB puede trabajar, y a
partir de él no se puede calcular un HMAC. **Una identidad que solo guarda
un hash NT sirve SMB y no S3**: vecinos cercanos, pero no la misma
respuesta. [`check`]({{< relref "/configuration/check.md" >}}) imprime la columna.
{{< /callout >}}

⛔ No existe ningún accesor `Password()` en todo el programa: a la contraseña solo
se llega mediante `Identity.Derive`, que recibe una derivación y devuelve su
resultado. Para S3 la derivación es la identidad, porque el cálculo de claves de
SigV4 vive en go-filesystems/s3; el secreto va a esa comprobación de firma, para ese
único usuario, y a ningún otro sitio.

## Lo que se sirve {#what-is-served}

`ListBuckets`, `HeadBucket`, `ListObjectsV2` con prefijo, delimitador, max-keys y
continuación, `HeadObject`, y `GetObject` con `Range`. SigV4 en sus dos formas, en
cabecera y prefirmada.

La API de objetos en sí es
[`go-filesystems/s3`](https://github.com/go-filesystems/s3).

## Lo que se rechaza, y por qué {#what-is-refused-and-why}

{{< callout type="warning" >}}
**Las escrituras responden 403**

`PUT`, `POST` y `DELETE` se rechazan con `AccessDenied` ("this export is
read-only"). fileshare mantiene el servidor S3 en solo lectura porque un
recurso compartido que una persona solo puede leer tiene que rechazar en el
mismo punto en que lo hace SFTP, y eso aún no está conectado;
go-filesystems/s3 v0.3.0, sobre la que se construye esta versión, rechaza de
todos modos cualquier escritura. Rechazar es mejor que un objeto escrito a
medias.
{{< /callout >}}

{{< callout type="warning" >}}
**Aquí no se acepta un token bearer**

[OIDC]({{< relref "/protocols/webdav.md" >}}) funciona por WebDAV y en ningún otro sitio. S3
autentica con una firma SigV4 —un HMAC sobre la petición—, sin ningún campo
en el que quepa un token bearer.

La vía es STS `AssumeRoleWithWebIdentity`, que canjea un token OIDC
por credenciales temporales con las que luego firma el cliente. Se sirve en
este listener desde v0.50.0: véase [abajo](#sts).
{{< /callout >}}

La subida multiparte, el versionado, las ACL, las políticas, las reglas de ciclo de
vida, la replicación y el etiquetado no están implementados. Configurar cualquiera de
ellos, e iniciar una subida multiparte, es una escritura, y responde `AccessDenied`
como cualquier otra. Un `GET` que pide uno de ellos (`?versioning`, `?acl`,
`?tagging`...) no se distingue: la consulta se ignora y se devuelve el listado del
bucket o el objeto. `NotImplemented` responde a un listado distinto de
`list-type=2`, a cualquier método salvo `GET` sobre `/`, y a un método que ninguna
operación de aquí utiliza.

## Credenciales temporales: STS `AssumeRoleWithWebIdentity` {#sts}

Desde v0.50.0 el listener S3 también responde a la API STS de AWS
(`AssumeRoleWithWebIdentity`, versión 2011-06-15): un token del proveedor del
[bloque `oidc`]({{< relref "/protocols/webdav.md" >}}) se canjea por una clave de acceso, una clave secreta y un token de
sesión que **caducan**. `aws`, `rclone` y los SDK de AWS lo hablan como con AWS, y nadie
guarda una contraseña.

```hcl
oidc {
  issuer   = "https://login.example.org"
  audience = "fileshare"
}

serve "s3" {
  addr             = "0.0.0.0:9000"
  tls              = true
  sts              = true      # POST / con Action=AssumeRoleWithWebIdentity
  sts_duration     = "1h"      # el valor por defecto, de 15m a 12h
  sts_max_duration = "4h"      # lo máximo que puede pedir DurationSeconds; por defecto sts_duration
  static_keys      = false     # se acabó «la clave de acceso es un usuario»: solo firman las credenciales temporales
}
```

- **El token** es un token de acceso (`typ` `at+jwt`) del proveedor del bloque `oidc`, para el
  emisor y la audiencia de ese bloque: no hay una segunda configuración de proveedor. El token de
  una persona o el de una máquina: el token `client_credentials` de go-authn/bridge para un cliente
  que se autentica con una clave privada (`private_key_jwt`) tiene `sub` = el ID del cliente, que
  es el nombre aquí.
- ⛔ **Pasa por la misma regla que un token por WebDAV.** Un token válido para un nombre que
  ninguna fuente de aquí conoce se rechaza, salvo `trust_all = true` o que la regla `oidc:` de un
  recurso compartido lo nombre (`allow = ["oidc:user:winpc-17"]`). Las reglas del recurso deciden
  entonces qué es visible.
- **La respuesta** es `AccessKeyId` (`ASIA…`), `SecretAccessKey`, `SessionToken` y `Expiration`.
  Las peticiones se firman con ellos y llevan el token de sesión en `x-amz-security-token`,
  **firmado**. Son aleatorios, solo en memoria y nunca se escriben; un reinicio los termina y el
  cliente vuelve a pedir.
- ⛔ **Duración = mín(pedida, lo que le queda al token).** Las credenciales nunca sobreviven al token
  que las compró (`sts_duration`, o `DurationSeconds` hasta `sts_max_duration`, es solo el techo).
  Un token al que le quedan **menos de 6 minutos** se rechaza con `ExpiredTokenException`: los SDK
  de AWS renuevan unos 5 minutos antes de `Expiration`, y unas credenciales más cortas se
  renovarían al instante, para siempre. Un cliente presenta un token nuevo en cada canje.
- ⛔ **Una sesión se juzga en cada petición**: caduca; su token de sesión está ligado a su clave de
  acceso; termina cuando el proveedor revoca a la persona después de emitido el token
  ([señales compartidas]({{< relref "/security/shared-signals.md" >}})); y cuando la configuración
  deja de admitir el nombre.
- `Policy`, `PolicyArns` y un segundo `WebIdentityToken` se rechazan, y los parámetros van en el
  cuerpo del POST, nunca en la URL.
- **`static_keys = false`** desactiva el modo «la clave de acceso es un usuario, la clave secreta es
  su contraseña». Necesita `sts = true`: si no, la configuración se rechaza al cargar, porque un
  listener para el que nadie podría firmar parecería configurado. En una dirección que no es de
  loopback, `sts` necesita `tls = true`, o `plaintext = true` cuando el TLS se termina delante.

### En una máquina desatendida: awscred {#on-an-unattended-machine-awscred}

[`awscred`](https://github.com/go-authn/awscred) v0.1.0 es un `credential_process` de AWS para
máquinas que tienen una clave privada y ninguna contraseña: firma un `private_key_jwt`, obtiene un
token de go-authn/bridge, llama a este endpoint e imprime las credenciales como las leen los SDK.
Los SDK lo ejecutan de nuevo antes de `Expiration`.

```ini
[profile fileshare]
credential_process = awscred --issuer https://login.example.org --client winpc-17 --key /etc/awscred/winpc-17.pem --sts https://s3.example.org
```

⛔ En Unix, `awscred` rechaza un archivo de clave legible por el grupo o por otros (`chmod 600`).
En Windows los modos de archivo no significan nada: guarde la clave en el perfil de la cuenta de
servicio o en un directorio cuya ACL admita solo esa cuenta. Una clave en el almacén CNG de
Windows o en un TPM aún no se admite.

### Detrás de un proxy: `trusted_proxies` {#behind-a-proxy-trusted_proxies}

Detrás del proxy para el que existe `plaintext = true`, todos los clientes serían una sola fuente
para los límites de abajo. Nombre los proxies en el bloque serve de `s3`:

```hcl
serve "s3" {
  addr            = "127.0.0.1:9000"
  plaintext       = true
  sts             = true
  trusted_proxies = ["10.0.0.2", "10.0.1.0/29"]
}
```

Solo a una petición que llega **desde** un proxy de confianza se le cree sobre su cliente, mediante
el salto más a la derecha de `X-Forwarded-For` que no sea a su vez un proxy de confianza; de
cualquier otro la cabecera se ignora.

{{< callout type="warning" >}}
**La lista debe nombrar los proxies y nada más**

Un prefijo más ancho que un host (un `/24`, un `/64` IPv6) se acepta —un conjunto de proxies, un
`/29`, es legítimo— y se imprime una advertencia al arrancar: un cliente que pueda tener una
dirección dentro elige su propio `X-Forwarded-For` y, con él, el cubo en el que se le cuenta.
{{< /callout >}}

### Límites {#limits}

- **16 sesiones por nombre**: la más antigua del mismo nombre sale primero, las sesiones de otros
  nombres se quedan (20000 en total).
- **60 peticiones por minuto por dirección de origen**, con respuesta `429 Throttling`. Cada
  petición cuenta, válida o no, antes de verificar el token. Un origen es una dirección IPv4 o un
  **/64** IPv6.
- El conteo es O(1) por petición, bajo su propio cerrojo, en un minuto deslizante de dos
  generaciones; las peticiones S3 con credenciales nunca esperan por él.
- Un origen visto en el último minuto se cuenta mientras la tabla tenga menos de **2 × 10000**
  entradas (la cota, por mucho que dure una avalancha). Un origen que la tabla llena no ha visto se
  cuenta en un cubo de desbordamiento de su red —su **/48** (IPv6) o **/24** (IPv4), diez veces la
  tasa cada uno—, de modo que una avalancha agota los cubos de las redes de las que viene, no los de
  todos. Los vecinos IPv4 detrás de un /24 (CGNAT, un campus) comparten un cubo.
- ⛔ **Pasadas 1024 redes por minuto, un cubo compartido atiende al resto**: un atacante con más redes
  lo agota, y todo origen que la tabla no haya visto ya —**incluidos los clientes existentes que
  renuevan más o menos cada hora**— es rechazado hasta que cambia el minuto. Es el límite de este diseño.

## Dos límites que conviene conocer antes de apuntarlo a algo grande {#two-limits-worth-knowing-before-pointing-it-at-something-large}

**`GetObject` lee el objeto entero en memoria.** La interfaz del controlador ofrece
`ReadFile` y nada más —ni función de apertura, ni lector—, así que no hay lectura en
streaming que usar. Un límite, 256 MiB, responde `EntityTooLarge` en lugar de tumbar
el proceso.

**`LastModified` es la época Unix.** `filesystem.Stat` lleva `Mode`, `Size` e
`Inode`, y ninguna fecha de modificación. El campo no es opcional en el esquema de
S3, así que hay que enviar algo; la época es obviamente una fecha que no es real,
mientras que `time.Now()` parecería un archivo que acaba de cambiar y haría que
cualquier herramienta de sincronización lo copiara todo, en cada ejecución.
