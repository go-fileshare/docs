v0.39.0부터 파일의 시간은 요청 시각이 아니라 해당 파일 시스템이 기록한
시간입니다. 이를 위해서는 `go-filesystems/interface` v0.6.0의 선택적 기능인
`TimesReader`가 필요하며, 드라이버가 이를 갖고 있을 수도 없을 수도 있습니다.

## 실제 시간을 알려 주는 공유 {#which-shares-report-real-times}

| 공유 | 실제 시간 |
|---|---|
| **디렉터리**(호스트) | 예: 접근, 수정, 변경, 그리고 호스트가 보관하는 경우 생성 시간. 나노초 단위 |
| **FAT 이미지** | 예, FAT의 해상도로: 수정 2초, 접근 1일, 생성 10ms. 변경 시간은 없음 |
| **exFAT 이미지**(v0.40.0부터) | 예: 생성과 수정 10ms, 접근 2초. 변경 시간은 없음 |
| **NTFS 이미지**(v0.40.0부터) | 예: 생성, 수정, 변경, 접근. 100ns |
| **ext4 이미지**(v0.40.0부터) | 예: 접근, 수정, 변경은 1ns(ext2/ext3의 128바이트 inode에서는 1초). 생성 시간은 inode가 충분히 클 때만 |
| **HFS+ 이미지**(v0.40.0부터) | 예: 생성, 수정, 변경, 접근. 1초 |
| 그 밖의 이미지 형식 | 이전처럼 응답 |
| 사용자 본인으로 제공되는 공유(`remote` 워커) | 예, 워커의 디렉터리가 호스트 디렉터리인 경우: 시간이 워커 경계를 넘어 전달됨 |

시간은 형식의 해상도와 프로토콜의 해상도 중 **더 거친 쪽**으로 비교됩니다.
SFTP는 정수 초, WebDAV의 `getlastmodified`도 정수 초, SMB는 100ns, NFS는
1ns입니다.

## 시간이 기록되지 않았을 때 {#when-a-time-is-not-recorded}

| 프로토콜 | 전송되는 값 |
|---|---|
| **SMB** | 0(「지정되지 않음」). 이 기능이 없는 드라이버는 여전히 현재 시각을 답합니다. |
| **NFS** | 접근 시간이나 변경 시간이 없으면 수정 시간이 되고, 수정 시간이 없으면 서버 시작 시각이 됩니다. |
| **SFTP** | 수정 시간이 없으면 `ACMODTIME` 플래그를 지웁니다. 클라이언트는 잘못된 시간 대신 시간 없음으로 봅니다. |
| **WebDAV** | `creationdate`는 생성 시간입니다. 기록되지 않은 시간은 응답에 나타나지 않습니다. |

## SMB에서 클라이언트가 설정하는 시간 {#setting-times}

v0.41.0부터(`go-filesystems/smb` v0.10.0,
go-filesystems/smb#45) 클라이언트가 SMB로 설정한 접근 시간과 수정 시간
(`SET_INFO`. `touch`, `robocopy /COPY:T`, 탐색기에서의 복사가 하는 동작)이
**디렉터리** 공유의 파일에 적용됩니다. 값이 0인 시간은 그대로 둡니다. -1은 그
시간을 고정하고 -2는 다시 재개합니다(열린 핸들마다).

저장할 수 없는 시간은 **기본적으로 무시됩니다**. 요청은 성공하고 해당 필드만
버려집니다(Samba와 같은 동작이며, 시간을 보존하는 복사가 실패하지 않게 하기
위해서입니다). 대상은 생성 시간, 단독으로 전송된 변경 시간, 시간을 설정할 수
없는 드라이버의 모든 시간입니다. fileshare에는 이를 위한 설정이 없으며 모든
공유가 기본값을 사용합니다.

### 동작 선택: `unstorable_times` {#unstorable-times}

v0.42.0부터 공유마다 `unstorable_times`로 이런 시간을 어떻게 처리할지 정할 수
있습니다(`go-filesystems/smb`의 `UnstorableTimes` 옵션).

```hcl
share "attic" {
  directory        = "/srv/attic"
  unstorable_times = "refuse"   # "ignore"(기본값), "refuse", "log"
}
```

| 값 | 클라이언트가 받는 응답 | 유지되는 것 |
|---|---|---|
| `ignore`(설정이 없을 때도) | 성공 | 해당 필드는 버려짐(Samba와 동일) |
| `refuse` | `STATUS_NOT_SUPPORTED`. 백업 도구가 시간이 보존되었다고 오해하지 않도록 하기 위함 | 해당 요청의 내용은 아무것도 적용되지 않음 |
| `log` | 성공 | 해당 필드는 버려지고, 요청마다 공유 이름, 경로, 필드를 적은 한 줄이 서버가 자신의 줄을 쓰는 곳에 기록됨 |

그 밖의 값은 구성을 읽을 때 공유 이름과 세 가지 값을 밝히는 오류로 거부됩니다.
이 설정은 SMB의 것입니다. `protocols`에 SMB가 빠진 공유가 이를 설정하면
거부됩니다. 서버 전체의 기본값은 없으며 공유마다 지정합니다. 관리 API로 만든
공유는 `ignore`를 사용합니다.

### 시간을 저장할 수 없는 경우 {#when-unstorable}

요청은 필드별로 판단되며, 저장할 수 없는 필드가 하나만 있어도 충분합니다.
`refuse`는 요청 전체를 거부하고 `log`는 한 줄을 씁니다. 다음의 경우 시간은 저장할
수 없습니다.

1. **CreationTime**이 드라이버가 보고하는 값과 다른 값으로 설정된 경우(또는
   드라이버가 아무것도 보고하지 않는 경우). 생성 시간을 설정할 방법은 없습니다.
   보고된 값과 같은 값은 받아들여집니다(바꿀 것이 없기 때문입니다).
2. **ChangeTime**이 **단독으로** 전송되었고 그 값이 보고된 값과 다른 경우.
   접근 시간 또는 수정 시간과 함께 전송되면, 드라이버가 시간을 설정할 수 있는
   경우 받아들여집니다. 시간을 설정하면 변경 시간이 "지금"으로 갱신되기
   때문입니다.
3. 시간을 설정할 수 없는 드라이버(`Chtimes` 없음)의 공유에서의 **접근 시간 또는
   수정 시간**: 현재 값과 같든 아니든 모든 실제 값이 해당합니다.

세 가지는 정책이 결정하지 않습니다. 0(유지), -1(고정), -2(재개)인 시간은 저장
불가가 되는 일이 없습니다. 시간을 설정할 수는 있지만 보고할 수 없는 드라이버에서의
-1은 모든 모드에서 항상 `STATUS_NOT_SUPPORTED`입니다. 이는 기능이 없는 것이지
버려진 필드가 아닙니다(ufs, btrfs, xfs, zfs 이미지가 해당합니다). 그리고
**읽기 전용** 공유(`read_only = true`, 장치, 파티션을 선택한 공유, 쓰기 권한이 없는
사람)에 대한 요청은 이 모든 것보다 먼저, 모든 모드에서 `STATUS_MEDIA_WRITE_PROTECTED`로
응답됩니다.

공유가 무엇을 저장할 수 있는지는 드라이버에 달려 있습니다(이 릴리스가 고정한
버전 기준).

| 공유 | CreationTime | ChangeTime 단독 | 접근 시간 또는 수정 시간 |
|---|---|---|---|
| **디렉터리**(호스트) | 보고된 생성 시간과 같지 않으면 저장 불가 | 보고된 값과 같지 않으면 저장 불가 | 저장됨(함께 전송된 ChangeTime은 허용) |
| **이미지, `Chtimes`가 있는 드라이버**: ext4, ufs, btrfs, xfs, zfs | 보고된 값과 같지 않으면 저장 불가(보고하는 것은 ext4뿐이며 나머지는 항상 불가) | 동일 | 저장됨(함께 전송된 ChangeTime은 허용) |
| **이미지, FAT 또는 exFAT** (v0.43.0부터) | 보고된 값과 같지 않으면 저장 불가(둘 다 보고함) | 동일 | 형식의 해상도로 저장됨: FAT는 수정 시간 2초(내림), 접근 시간은 날짜만; exFAT는 수정 시간 10 ms, 접근 시간 2초(함께 전송된 ChangeTime은 허용) |
| **이미지, HFS+** (v0.44.0부터) | 보고된 값과 같지 않으면 저장 불가(보고함) | 동일 | 1초 단위로 저장됨(함께 전송된 ChangeTime은 허용). 저널 때문에 공유가 [읽기 전용]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}})이 된 경우는 제외 |
| **이미지, `Chtimes`가 없는 드라이버**: NTFS, APFS, ISO 9660, SquashFS | 동일(NTFS는 보고하고 나머지는 보고하지 않음) | 동일. 접근 시간 또는 수정 시간과 함께여도 **마찬가지** | **항상 저장 불가** |

`Chtimes`가 있는 드라이버는 osfs(`osfs.go:383`), ext4(`metadata.go:93`), ufs
(`metadata.go:63`), btrfs(`fs.go:382`), xfs(`fs.go:521`), zfs(`metadata.go:94`)이며,
v0.43.0부터는 fat32 v0.13.0과 exFAT v0.6.0도 포함됩니다(전체 `MetadataSetter`: FAT에는
모드 비트와 소유자가 없으므로 이들의 `Chmod`와 `Chown`은 "지원되지 않음"을 반환합니다).
따라서 FAT 또는 exFAT 이미지 공유에서의 `touch -d`와 `cp -p`는 저장됩니다. 나머지에는 없습니다.
HFS+에도 있습니다. hfsplus v0.8.0은 `Chtimes`, `Chmod`, `Chown`을 구현하며,
v0.44.0(hfsplus v0.9.0)부터 제공되는 HFS+ 이미지는 쓰기 가능으로 열리므로
SMB로 설정한 시간이 저장됩니다. 트랜잭션이 남아 있는 저널이 있는 이미지는
대신 읽기 전용으로 열리며 아무것도 저장하지 않습니다
([HFS+ 이미지는 쓰기 가능]({{< relref "/configuration/shares.md#hfsplus-images-are-writable" >}}) 참조). v0.42.0 이전에는 fileshare가 모든 이미지 드라이버 앞에 두는
잠금이 `Chtimes`를 숨겨서 ext4를 포함한 모든 이미지가 클라이언트의 접근 시간과 수정
시간을 버렸습니다. v0.42.0부터는 드라이버에 있을 때에 한해 `Chtimes`를 전달합니다.
NTFS 이미지는 읽기 전용 드라이버가 읽으므로 정책과 관계없이 아무것도 저장되지 않으며,
정책은 클라이언트에 무엇을 알릴지만 결정합니다.

어떤 클라이언트가 어떤 경우에 해당하는가: Windows 탐색기와 `robocopy /COPY:T`는
CreationTime을 보내며, 변하지 않은 경우가 아니면 어떤 종류의 공유도 이를 보존할 수
없습니다. Linux의 `touch -d`와 `cp -p`는 접근 시간과 수정 시간만 보냅니다(커널
클라이언트는 "지금"의 ChangeTime을 덧붙입니다). 디렉터리와 `Chtimes`가 있는
드라이버는 이를 저장하고, 없는 드라이버는 저장하지 못합니다.
